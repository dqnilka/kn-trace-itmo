## 1. Где используется

ML задействован в **шести модулях** проекта:

| Модуль | Файлы | Роль |
|--------|-------|------|
| **Построение графа знаний (offline)** | `vendor/k2-18/src/` (slicer, itext2kg_concepts, itext2kg_graph, dedup, refiner_longrange) | Извлечение концептов, чанков и связей из учебника через LLM + эмбеддинги |

| **BKT + FSRS (online)** | `app/exams/bkt.py` | Отслеживание уровня знаний студента по каждому концепту |
| **Адаптивный рекомендер (online)** | `app/services/recommend.py` | Выбор следующей задачи с оптимальной сложностью |
| **Генерация сводок тем (on-demand)** | `app/services/theme_summary.py`, `app/services/bank_explain.py` | LLM-генерация описаний тем и объяснений ошибок |

## 2. Как используется

### 2.1. Построение графа знаний (vendor/k2-18)

**5-стадийный offline-пайплайн:**

1. **Нарезка текста (slicer):** Учебник (1.8 МБ) нарезается на слайсы по ~15 000 токенов с поиском семантических границ (заголовки > абзацы > предложения).
2. **Извлечение концептов (itext2kg_concepts):** LLM (GPT-5) последовательно обрабатывает слайсы, извлекая концепты (термин + определение + алиасы). Каждый слайс получает контекст всех предыдущих через `previous_response_id`.
3. **Построение графа (itext2kg_graph):** LLM разбивает текст на Chunk-узлы, связывает с Concept-узлами, создаёт рёбра (PREREQUISITE, ELABORATES, TESTS, MENTIONS, EXAMPLE_OF, PARALLEL). MENTIONS-рёбра также генерируются автоматически через regex по тексту чанка.
4. **Дедупликация (dedup):** Эмбеддинги узлов → FAISS HNSW → Union-Find кластеризация дубликатов (порог cosine ≥ 0.85).
5. **Поиск длинных связей (refiner_longrange):** FAISS-поиск похожих узлов → LLM-классификация типа ребра (прямой и обратный проход).

**Результат:** 758 концептов, 1223 узла, ~3000 рёбер.

### 2.2. Пайплайн связывания (app/pipeline)

1. **Task → Concept:** E5-эмбеддинги задач и концептов → cosine similarity → top-3 концепта с score ≥ 0.35. Опционально: LLM-переранжирование (GPT).
2. **Concept → Theme:** Majority-vote — концепт привязывается к теме, из которой больше всего связанных задач.
3. **Prerequisites:** LLM по главам извлекает PREREQUISITE-рёбра между концептами одной главы (бинарные, score=1.0).
4. **Theme → Theory:** E5-эмбеддинги тем → поиск по ChromaDB md_chunks → top-6 секций с cosine ≥ 0.35.

### 2.3. RAG-пайплайн (online)

**Два пути:**

**Путь A — Графовый RAG** (для задач с BFS-расширением):
1. BFS от узла задачи (глубина 2) → извлечение связанных узлов.
2. Формирование запроса: текст вопроса + top-6 расширений.
3. Векторный поиск по 3 коллекциям ChromaDB (graph_chunks, graph_concepts, md_chunks).
4. Графовый буст: `score = base + 0.25 * (1 - base)` для узлов из BFS.
5. Дедупликация: md_chunks с Jaccard ≥ 0.7 против graph_chunks удаляются.
6. Cross-encoder переранжирование: blend = 0.5 × CE + 0.5 × retrieval.
7. LLM-генерация (gpt-4o-mini) с контекстом до 6000 символов.

**Путь B — Bank explain** (для задач из банка):
1. Запрос = текст задачи + правильный ответ + название темы.
2. Векторный поиск по коллекциям экзамена.
3. Буст тематических секций: `score + 0.18 * (1 - score)`.
4. LLM-генерация с кэшированием по (exam, task_id, picked_label).

### 2.4. BKT + FSRS (online)

При каждом ответе студента:

1. **BKT (4-параметрический):** Обновление P(L) по каждому связанному концепту:
   - correct: `P(L|c=1) = [P(L)·(1-P(S))] / [P(L)·(1-P(S)) + (1-P(L))·P(G)]`
   - incorrect: `P(L|c=0) = [P(L)·P(S)] / [P(L)·P(S) + (1-P(L))·(1-P(G))]`
   - переход: `P(L_{t+1}) = P(L|c) + (1 - P(L|c))·P(T)`

2. **FSRS-lite:** Обновление стабильности памяти:
   - correct: `S_new = S_prev · max(1.0, 1.7 - (R - 0.5))`
   - incorrect: `S_new = max(3600, S_prev · 0.4)`
   - retrievability: `R(t) = exp(-(now - last_seen) / stability)`

### 2.5. Адаптивный рекомендер (online)

Для каждого кандидата-задачи:
1. `weighted_p` — взвешенное P(correct) по связанным концептам.
2. `proximity = 1 - |weighted_p - 0.65|` — зона ближайшего развития.
3. `gain = H(p) = -p·log(p) - (1-p)·log(1-p)` — информационная выгода (энтропия Бернулли).
4. `due_score = max(0, 1 - avg_retrievability)` — давление повтора (FSRS).
5. `prereq_readiness` — среднее P(L) по пререквизитам.
6. **Итоговый score** = `(0.55·proximity + 0.25·gain + 0.20·due_score) · (0.6 + 0.4·readiness)`

Фильтры: cooldown (12 последних задач), вето по пререквизитам (≥2 слабых и readiness < 0.35 → пропуск), отсев mastered (weighted_p > 0.92 и retrievability > 0.85).

## 3. Что применяется

### 3.1. Модели эмбеддингов

| Модель | Размерность | Где используется |
|--------|-------------|------------------|
| **intfloat/multilingual-e5-small** | 384 | Пайплайн связывания, RAG (ChromaDB), кластеризация тем |
| **text-embedding-3-small** (OpenAI) | 1536 | k2-18: дедупликация и поиск длинных связей (FAISS) |

### 3.2. Ранжирующие модели

| Модель | Где используется |
|--------|------------------|
| **cross-encoder/mmarco-mMiniLMv2-L12-H384-v1** | Переранжирование RAG-результатов (blend=0.5) |

### 3.3. LLM (генерация)

| Модель | Где используется | Роль |
|--------|------------------|------|
| **gpt-4o-mini** | RAG-генерация объяснений, сводки тем | Ответы студенту |
| **gpt-5 / gpt-5-nano / gpt-4.1-mini / gpt-4.1-nano** | k2-18: извлечение концептов и графа, переранжирование, пререквизиты | Построение графа знаний |

### 3.4. Алгоритмические модели

| Алгоритм | Где используется |
|----------|------------------|
| **4-параметрический BKT** (P(L₀)=0.3, P(T)=0.1, P(G)=0.2, P(S)=0.1) | Отслеживание мастерства |
| **FSRS-lite** (4 константы) | Интервальное повторение |
| **KMeans** | Кластеризация концептов в темы (n_topics=15) |
| **FAISS HNSW** | k2-18: поиск ближайших соседей для дедупликации и длинных связей |
| **BFS (depth=2)** | Графовое расширение при RAG-поиске |
| **Cosine similarity** (brute-force / ChromaDB HNSW) | Векторный поиск повсюду |

## 6. Как сейчас оценивается результат

### 6.1. Граф знаний (k2-18) — **нет автоматической оценки качества**

- **Schema-валидация:** JSON Schema (Draft 202012) для ConceptDictionary и LearningChunkGraph.
- **Инварианты:** Нет дублей node_id, все source/target существуют, нет PREREQUISITE self-loops, нет дублей (source, target, type).
- **Нет метрик качества рёбер** (precision/recall/F1 против эталона).
- **Нет человеческой оценки** связей.
- Параметры LLM-промптов и пороги заданы эвристически.

### 6.2. Пайплайн связывания — **нет систематической оценки**

- Пороги (min_score=0.35, top_k=3) заданы эвристически.
- LLM-переранжирование — fallback на top-2 эмбеддинга при ошибке.
- **Нет замеров precision/recall** связывания задач с концептами.
- **Нет ground truth** для оценки.

### 6.3. RAG — **частичная оценка через тесты**

| Что проверяется | Метод | Файл теста |
|-----------------|-------|------------|
| Add+search round-trip | Self-similarity > 0.99 | `test_vectorstore.py` |
| Корректность chunking | Уникальные ID, метаданные | `test_md_chunker.py` |
| Retriever: графовое расширение | Узел из BFS в результатах | `test_retriever.py` |
| Dedup Jaccard | Одинаковый текст → дроп | `test_retriever_extra.py` |
| Graph boost | ≥2 различных скора | `test_retriever_extra.py` |
| Reranker blending | Min-max норм., blend-формула | `test_reranker.py` |
| Extractive fallback | Нет LLM-вызова, текст > 100 символов | `test_generator_extractive.py` |

- **Нет оценки качества генерации** (fluency, faithfulness, relevance).
- **Нет RAGAS / LLM-as-judge метрик** (context precision, answer relevancy, faithfulness).
- **Нет A/B тестирования** разных prompt-стратегий.

### 6.4. BKT / FSRS — **нет тестов вообще**

- **Нет юнит-тестов** на BKT, FSRS, рекомендер, events.
- **Нет оценки предсказательной способности** (AUC, RMSE, MAE на исторических данных).
- **Нет сравнения** с baseline (случайный выбор, Popularity-based).
- Параметры BKT (P(L₀)=0.3, P(T)=0.1, P(G)=0.2, P(S)=0.1) — литературные дефолты, **не фитированные на данных**.
- FSRS-константы — упрощённые, **не калиброванные**.
- Weight (task→concept similarity score) записывается в события, но **не используется** при BKT-обновлении (закомментировано как future tuning knob).

### 6.5. Рекомендер — **нет оценки**

- **Нет offline-оценки** на исторических данных (например, leave-one-out).
- **Нет A/B тестирования** online.
- Веса в скоринге (0.55, 0.25, 0.20) — эвристические, **не оптимизированные**.

### 6.6. Генерация сводок тем — **нет оценки**

- Кэширование по SHA-256 хешу контента.
- **Нет оценки качества** сводок (полнота, точность, стиль).
